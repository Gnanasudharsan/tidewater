Real-time CDC lakehouse

At-least-once delivery in. Exactly-once results out.

Tidewater streams every change from Postgres through Debezium and Kafka into Delta Lake and a warehouse. Kafka may deliver an event twice, late, or out of order; one LSN-guarded MERGE makes the result exactly right anyway.

Try to break it

Change the source table, then attack the delivery: redeliver events, shuffle them, kill Spark mid-batch, replay everything. Both sinks get exactly the same deliveries. The naive sink applies them in arrival order; Tidewater applies each micro-batch with the production MERGE rule.

This is a simulation running in your browser, not the live pipeline. It uses the same merge rule as the real Spark job, ported to merge.js.

        Run it yourself

        The real stack, not the simulation. In a browser with GitHub Codespaces (a 4-core / 16 GB machine, on your own free Codespaces hours), or locally with Docker (about 6 GB of RAM for the core profile).

        Open in GitHub Codespaces

        git clone https://github.com/Gnanasudharsan/tidewater.git && cd tidewater
make up-core   # Postgres, Kafka, Debezium, registry, S3, bronze + silver streams
make demo      # 5 min: live load, SIGKILL mid-batch, recovery, then proof

        The demo ends by checking bronze (every Kafka offset exactly once), reconciling silver against the source, and tracing one order back to its WAL LSN. Grafana is on port 3001.
